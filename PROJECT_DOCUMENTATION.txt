1. PROJECT OVERVIEW
================================================================================

AutoMicro-Bot is a floating AI chatbot desktop application for macOS. It sits
as an always-on-top transparent widget on your screen — similar to Apple's
Dynamic Island — and lets you interact with a local AI assistant that can
execute terminal commands on your machine.

Key Characteristics:
  - Runs entirely on-device (privacy-first, no cloud required by default)
  - Powered by LangGraph ReAct agent with tool-calling capabilities
  - Supports multiple LLM providers (Ollama, OpenAI, Gemini, OpenAI-compatible)
  - Glassmorphism UI with dark/light theme support
  - Three view modes: Dynamic Island bubble, mini floating, and full desktop
  - Real-time SSE streaming with token-by-token responses
  - Tool call visualization with macOS Terminal emulation
  - Persistent chat history with session management
  - Configurable safety guards to prevent dangerous commands

5. DATA FLOW & COMMUNICATION
================================================================================

5.1 CHAT MESSAGE FLOW (Streaming)
─────────────────────────────────

  1. User types message in InputBar → calls handleSend(text, attachment)
  2. App.jsx adds user message to local state, creates placeholder assistant msg
  3. streamMessage() in chat.js sends POST /chat/stream with:
     - session_id, message, optional attachment (file content as base64/text)
  4. Backend chat.py receives request:
     a. Creates conversation in DB if first message
     b. Saves user message to DB
     c. Loads message history from DB (last 50 messages)
     d. Calls LangGraph agent via app.astream()
  5. Agent processes with LLM:
     a. LLM decides to respond or use tools
     b. If tool call → executes terminal command → returns output
     c. LLM may iterate (multiple tool calls per turn)
  6. Backend streams SSE events:
     - event: token     → individual text tokens
     - event: tool_start → tool name + arguments
     - event: tool_command → the command being executed
     - event: tool_output → tool execution result
     - event: done      → final complete response
     - event: error     → error message
  7. Frontend parses SSE events:
     - Tokens appended to assistant message content
     - Tool calls added to message commands array
     - UI updates in real-time (typing indicator, tool blocks)
  8. On "done", saves assistant message to DB

5.2 SETTINGS FLOW
──────────────────

  Permissions:
    Frontend SettingsDrawer → settings.js API → settings.py route
    → permission_manager.py → tool_permissions.json (disk)

  LLM Config:
    Frontend SettingsDrawer → settings.js API → settings.py route
    → database.py (llm_settings + llm_history tables) → reset_agent()

5.3 HISTORY FLOW
────────────────

  Frontend HistoryDrawer → chat.js API → chat.py route → database.py
  Operations: list sessions, load messages, rename, delete, clear

────────────────────────────────────────────────────────────────────────────────

Purpose: Creates and configures the FastAPI application instance.

Key Components:
  - FastAPI app with title "AutoMicro-Bot API"
  - CORS middleware configured from CORS_ORIGINS env var

  - Health check at GET /
  - start() function runs Uvicorn on 127.0.0.1:8000 with reload

6.4 LANGGRAPH AGENT — app/graph/agent.py
────────────────────────────────────────────────────────────────────────────────

Purpose: The AI brain — configures and manages the LangGraph ReAct agent.

Key Globals:
  - _agent_app: Singleton LangGraph compiled application
  - _saver: AsyncSqliteSaver for conversation checkpointing (stm.db)
  - _current_provider / _current_model: Track active LLM

Key Functions:
  - reset_agent(): Clears singleton to force re-init on next call
  - build_system_prompt(state): Constructs the system message including:
    • macOS command reference guide
    • Tool usage instructions
    • Interruption handling rules
    • Dynamic permission rules (ALLOWED/FORBIDDEN) from config
    • Gemini-specific message sanitization
  - get_app(): Lazy-initializes the LangGraph app:
    • Reads LLM config from database
    • Instantiates appropriate LangChain LLM class
    • Creates AsyncSqliteSaver checkpointer
    • Builds create_react_agent with terminal tool
  - get_agent_response(session_id, message): Blocking invoke interface

Supported LLM Providers:
  - ollama / ollama-cloud  → ChatOllama
  - openai / openai-compat → ChatOpenAI
  - gemini                 → ChatGoogleGenerativeAI

Tools Bound: [execute_terminal_command] — single tool

Agent Type: LangGraph ReAct (reason + act loop)
  The agent receives the user message, reasons about what to do, optionally
  calls tools, observes results, and continues until it has a final answer.

6.5 TERMINAL EXECUTOR — app/graph/tools/terminal_executor.py
────────────────────────────────────────────────────────────────────────────────

Purpose: The only tool available to the agent — executes shell commands.

Function: execute_terminal_command(command: str) -> str
  - Decorated with @tool (LangChain) and @check_permission
  - Runs via subprocess.Popen() in user's home directory
  - 60-second timeout
  - Returns formatted output with exit code and elapsed time

Safety Guards (regex pattern groups):
  ┌──────────────────────────┬───────────────────────────────────────────────┐
  │ Guard Name               │ What It Blocks                               │
  ├──────────────────────────┼───────────────────────────────────────────────┤
  │ block_destructive_delete │ rm -rf /, rm -rf *, srm                      │
  │ block_disk_operations    │ mkfs, wipefs, dd, diskutil erase/partition   │
  │ block_system_power       │ shutdown, reboot                             │
  │ block_system_integrity   │ csrutil disable, nvram boot-args             │
  │ block_remote_code_exec   │ curl|sh, wget|sh                             │
  │ block_permission_changes │ chmod 777 /, chown -R /                      │
  │ block_fork_bomb          │ Fork bomb patterns, background disown        │
  └──────────────────────────┴───────────────────────────────────────────────┘

6.6 PERMISSION MANAGER — app/graph/tools/permission_manager.py
────────────────────────────────────────────────────────────────────────────────

Purpose: JSON-based permission system with caching and a decorator.

Key Constants:
  - BUILTIN_TOOLS: {"execute_terminal_command": True}
  - SAFETY_GUARDS: 7 guards, all default True (enabled)
  - DEPRECATED_TOOL_KEYS: ~25 old tool names, auto-stripped on load/save
  - CONFIG_PATH: app/graph/config/tool_permissions.json

Key Functions:
  - _sanitize_permissions(raw): Merges saved config with defaults, drops
    deprecated keys, preserves _locked_tools and custom rules
  - load_permissions(force_refresh): Loads from JSON with caching
  - save_permissions(permissions): Sanitizes and writes to disk
  - check_permission(tool_name): Parameterized decorator — if tool is
    disabled, returns "permission disabled" message instead of executing

Key Functions:
  - init_db(): Creates tables, runs migrations, seeds defaults from env

  - is_first_message(): COUNT check for session
  - get_llm_settings() / update_llm_settings()
  - get_llm_history() / save_llm_history() / delete_llm_history()

11. SECURITY & SAFETY SYSTEM
================================================================================

The safety system has two layers:

Layer 1 — Tool Permission Toggle:
  The execute_terminal_command tool can be entirely disabled via the
  @check_permission decorator. When disabled, any tool call returns
  "Tool execute_terminal_command is currently disabled" without executing.

Layer 2 — Safety Guard Patterns:
  Seven regex-based guards that block specific dangerous command patterns:

  1. block_destructive_delete (DEFAULT: ON)
     Blocks: rm -rf /, rm -rf *, srm (secure remove)
     Why: Prevents accidental filesystem destruction

  2. block_disk_operations (DEFAULT: ON)
     Blocks: mkfs, wipefs, dd, diskutil erase/partition
     Why: Prevents disk formatting and raw disk writes

  3. block_system_power (DEFAULT: OFF — currently disabled!)
     Blocks: shutdown, reboot, halt, poweroff
     Why: Prevents unintended system restarts

  4. block_system_integrity (DEFAULT: ON)
     Blocks: csrutil disable, nvram boot-args
     Why: Prevents SIP and firmware modification

  5. block_remote_code_exec (DEFAULT: ON)
     Blocks: curl|sh, wget|sh, curl|bash
     Why: Prevents running untrusted remote scripts

  6. block_permission_changes (DEFAULT: ON)
     Blocks: chmod 777 /, chown -R /
     Why: Prevents wide-open filesystem permissions

  7. block_fork_bomb (DEFAULT: ON)
     Blocks: :(){ :|:& };:, background disown patterns
     Why: Prevents system resource exhaustion

Custom Rules:
  Users can add custom rules that appear in the agent's system prompt as
  ALLOWED or FORBIDDEN instructions. These are advisory (prompt-based)
  rather than hard-blocked like safety guards.

Locked Tools:
  The _locked_tools list prevents specific tools from being toggled by
  the user in the settings UI.

13. SSE STREAMING PROTOCOL
================================================================================

The frontend communicates with the backend via Server-Sent Events (SSE)
for real-time streaming of AI responses.

Request:
  POST /chat/stream
  Content-Type: application/json
  Body: { session_id, message, attachment? }

Response: text/event-stream

Event Types:
  ┌──────────────┬──────────────────────────────────────────────────────────┐
  │ Event        │ Data Format / Purpose                                   │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ token        │ {"content": "partial text"}                             │
  │              │ Individual text token from the LLM response             │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ tool_start   │ {"tool": "execute_terminal_command", "args": {...}}     │
  │              │ Signals that a tool call is beginning                    │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ tool_command │ {"command": "ls -la"}                                   │
  │              │ The specific command being executed                      │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ tool_output  │ {"output": "...result...", "tool": "..."}               │
  │              │ Result of the tool execution                             │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ done         │ {"content": "full response text"}                       │
  │              │ Streaming complete, full assembled response              │
  ├──────────────┼──────────────────────────────────────────────────────────┤
  │ error        │ {"error": "error message"}                              │
  │              │ An error occurred during processing                      │
  └──────────────┴──────────────────────────────────────────────────────────┘

SSE Format:
  event: token\n
  data: {"content": "Hello"}\n
  \n

Frontend parses the stream using fetch() + ReadableStream reader,
splitting on double newlines. Supports AbortController for stop.
