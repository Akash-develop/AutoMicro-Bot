1) What this project is
-----------------------
AutoMicro-Bot is a floating desktop AI chatbot app:

- Desktop shell: Tauri (Rust)
- UI: React + Vite (with Bootstrap-based styling/components)
- Backend: FastAPI (Python) providing:
  - HTTP chat endpoint (blocking)
  - SSE chat streaming endpoint (token streaming + tool event streaming)
  - SQLite persistence (messages, conversations, LLM settings + history)
  - Optional long-term memory via ChromaDB
  - LangGraph/LangChain agent orchestration

The intended UX is an always-on-top, transparent “glass” widget that can also
switch into bubble mode and a larger “normal” desktop-sized mode.

3) Backend (Python / FastAPI)
-----------------------------

3.1 Entry point
---------------
File: back-end/app/main.py

- App name: "AutoMicro-Bot API"
- Default host/port for local dev:
  - host: 127.0.0.1
  - port: 8000
- CORS:
  - env var: CORS_ORIGINS
  - default: "http://localhost:5173,tauri://localhost"

3.2 API routes
--------------
File: back-end/app/routes/chat.py

HTTP:
- GET  /                          Health check: {"message": "...", "status": "online"}
- POST /chat                      Blocking chat (JSON: {session_id, message})
- POST /chat/stream               Streaming chat (SSE)

History / conversations:
- GET    /history                 List conversations (title, last active, etc.)
- GET    /history/{session_id}     Messages for a session (oldest → newest)
- DELETE /history/{session_id}     Delete a conversation + all messages
- DELETE /history/{session_id}/messages
                                  Clear messages only (keeps conversation record)
- PATCH  /conversations/{session_id}
                                  Rename conversation (JSON: {title})

Utility:
- POST /terminal/open              (macOS) opens Terminal.app in current dir

Streaming (SSE) message formats (as implemented)
------------------------------------------------
Client → server (HTTP JSON body):
{
  "session_id": "abc123",
  "message": "hi",
  "attachment": {
    "name": "file.png|notes.txt",
    "content": "<data-url-for-images OR raw text content for text files>",
    "mime_type": "image/png|text/plain|...",
    "size": 12345
  }
}

Server → client (SSE frames):
- event: token
  data: {"content":"..."}                     streamed assistant text
- event: tool_start
  data: {"command":"toolName"}                tool invocation started
- event: tool_output
  data: {"result":"..."}                      tool output chunk/result
- event: done
  data: {}                                    stream finished
- event: error
  data: {"content":"..."}                     error message

Notes:
- Text attachments are prepended into the user message.
- Image attachments are passed as multimodal content (text + image_url).

3.3 Agent orchestration
-----------------------
File: back-end/app/graph/agent.py

- Framework: LangGraph + LangChain "ReAct" agent (`create_react_agent`)
- Streaming:
  - SSE route uses `app.astream(..., stream_mode="messages")`
- State persistence (short-term memory / checkpointing):
  - AsyncSqliteSaver uses a separate SQLite file:
    - env var: STM_DB_PATH
    - default: "stm.db"
- LLM provider selection is dynamic and stored in SQLite (see DB section).
  Supported providers in code:
  - "ollama", "ollama-cloud" (ChatOllama)
  - "openai", "openai-compat" (ChatOpenAI with custom base_url)
  - "gemini" (ChatGoogleGenerativeAI)

Tools available to the agent (registered in `agent.py`)
-------------------------------------------------------
These are the actual built-in tools that permissions apply to:
- execute_terminal_command
- open_url
- search_web
- sleep_system
- create_folder
- create_file
- create_excel_with_sample_data
- save_long_term_memory

Tool permissions config
-----------------------
File path (backend):
  back-end/app/config/tool_permissions.json

Implementation:
- back-end/app/graph/tools/permission_manager.py
- Permissions are cached in memory and merged with defaults (BUILTIN_TOOLS).
- A tool can be blocked; blocked tools return a user-readable denial string.
- The settings API stores an additional key: "_locked_tools" (array of tool names).

3.4 Persistence (SQLite + ChromaDB)
-----------------------------------
SQLite (chat history + settings):
- File:
  - env var: DB_PATH
  - default: "./automicro.db" (relative to back-end working directory)
- Tables (created in `init_db()`):
  - messages (includes optional JSON "attachment")
  - conversations (session_id primary key + title)
  - llm_settings (single row id=1)
  - llm_history (history of configs with is_active flag)

ChromaDB (optional long-term memory):
- File/directory:
  - env var: CHROMA_DB_PATH
  - default: "./chroma_db"
- Collection:
  - "long_term_memory"
- Backing code:
  - back-end/app/db/chroma.py

- BASE_URL is hardcoded to: http://localhost:8000

UI modes (high level)
---------------------
File: front-end/src/App.jsx
- Generates and stores session id in localStorage ("automicro_session").
- Modes:

  - mini mode: smaller floating chat
  - normal mode: large layout with persistent sidebar/history
- Theme:
  - localStorage key "automicro_theme" ("dark" or "light")

7) Troubleshooting
------------------

Backend not reachable (UI errors / fetch fails):
- Ensure backend is running on http://localhost:8000
- Check CORS_ORIGINS includes the frontend origin:
  - http://localhost:5173
  - tauri://localhost

Streaming not working:
- Confirm backend endpoint: POST http://localhost:8000/chat/stream
- Confirm port 8000 is free and backend logs show stream requests.

“unauthorized” / “401” from an OpenAI-compatible provider:
- Verify base_url is correct for your provider.
- If using SiliconFlow, the backend includes a hint that base URL should be:
  https://api.siliconflow.cn/v1
- Do not use https://ollama.com as an API base URL (that is not an OpenAI-compatible API).

ChromaDB issues:
- If `back-end/app/db/chroma.py` cannot init the PersistentClient at CHROMA_DB_PATH,
  long-term memory may not work; check file permissions and folder existence.

Database files:
- The repo already contains DB files (e.g., automicro.db, stm.db) in back-end/.
  If you want a clean run, stop the backend and move/delete those files, then restart.


8) Security notes (local-first, but still important)
----------------------------------------------------
- Tool permissions exist for potentially sensitive capabilities (terminal execution,
  file creation, browser actions). Review and disable as needed in the UI.
- API keys may be stored in SQLite (llm_settings / llm_history). Treat DB files
  as sensitive if you use cloud providers.
